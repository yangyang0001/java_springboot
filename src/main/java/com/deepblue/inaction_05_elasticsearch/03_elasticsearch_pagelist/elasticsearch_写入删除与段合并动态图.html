频繁插入、删除与段合并

每个小方格是一篇文档。写入先进入内存 buffer，此时搜索不到；每次 refresh 把 buffer 生成一个新 segment，文档才能被搜索。删除只是打标记，段合并时已删除文档才被真正丢弃。

Segment 视图（单个分片）

buffer 中，搜不到 可搜索 已删除，refresh 前仍可搜到 已标记删除，仍占磁盘

虚线框是正在合并的 segment，底部进度条为合并进度；刚生成的 segment 会短暂高亮。合并只把存活文档写进新 segment。

插入 → 可搜索 时间线

每条横线是一篇文档：左端是写入时间，右端是被 refresh 变为可搜索的时间，竖虚线是 refresh。线越长，查询时差越大；红线表示还没 refresh 就被删掉的文档。

事件

    插入、删除与查询的时差对照

    操作什么时候能看到结果时差
    写入请求返回
    PUT /_doc/1、_bulk    		写入主分片的 buffer 和 translog，副本也写完后返回。默认 index.translog.durability=request，每个请求返回前 fsync translog。毫秒级
    按 ID 读取
    GET /_doc/1    		默认 realtime=true：文档还没 refresh 时也能读到（读 translog 或对该分片触发一次内部 refresh）。≈ 0
    搜索
    _search、_count    		只能搜到已 refresh 的 segment。写入后要等到下一次 refresh。0 ~ 1s
    平均约 0.5s
    写入时带 ?refresh=wait_for请求一直等到下一次 refresh 完成才返回，返回后立即可搜。写入变慢 ≤ 1s
    写入时带 ?refresh=true立即强制 refresh，返回后立即可搜。每次都产生一个小 segment，高频使用会加重合并压力。≈ 0，代价高
    分片 search idle（7.0+）未显式设置 refresh_interval 的分片 30s 没有查询时，跳过定时 refresh；下一次查询先等 refresh 再执行。首次查询变慢
    删除
    DELETE /_doc/1    		GET 立即返回 404；_search 在下一次 refresh 之前仍能搜到这篇文档。0 ~ 1s
    磁盘空间释放包含该文档的 segment 被合并、且旧 segment 不再被搜索 / scroll / PIT 引用后。soft deletes 保留期（默认 12h）内不会被清除。秒级 ~ 数小时
    flush（Lucene commit）translog 达到 index.translog.flush_threshold_size（默认 512MB）等条件时执行。只影响持久化和恢复，与是否可搜索无关。与可见性无关

    动画是缩小比例的示意：segments_per_tier 取 4（ES 默认 10），单个 segment 上限 480 篇代表 max_merged_segment 5GB，deletes_pct_allowed 为 20%，translog 3000 次操作代表 512MB。存活文档超过 2400 篇后，删除速度自动提高到与插入相同，让画面保持在可看的规模。
